## 1. Objective / Aim
To integrate an external Generative AI service (Google Gemini API / OpenAI API) into a full-stack Task Management web application, implementing secure server-side API key management, client rate limiting, responsible data governance, and robust graceful degradation so the application remains fully functional even when third-party AI services are offline or throttled.

## 2. Theory & Concepts

### 2.1 Why External AI Must Be Brokered Through the Backend
Calling third-party AI APIs directly from client-side single-page applications (React) is an acute security vulnerability:
1. **Credential Exposure:** Browser network requests expose the secret API key in plain text in the Network tab, allowing anyone to steal the key and incur financial costs.
2. **Abuse & Cost Overruns:** Without a backend gateway, malicious actors can send infinite automated prompts directly to the provider.
3. **Data Exfiltration:** Backend brokering ensures strict governance over what payload leaves the organization.

In our architecture, the React frontend only communicates with `POST /api/ai/generate-description`. The secret key (`GEMINI_API_KEY` or `OPENAI_API_KEY`) resides exclusively in the server `.env` file and is never transmitted to the browser.

### 2.2 Graceful Degradation in Microservices
Third-party AI APIs are subject to external failure modes:
- Rate limiting / HTTP 429 quota exhaustion
- Network timeouts and regional outages
- Invalidation or revocation of billing keys

Graceful degradation means designing software such that a third-party failure does not cascade into a system-wide crash. If the AI call fails or times out:
1. The backend catches the exception.
2. It returns a structured JSON fallback response (`fallback: true`).
3. The React UI displays an informational alert and allows the user to manually enter the description.
4. Core task creation, reading, updating, and deletion in MongoDB remain 100% operational.

### 2.3 Responsible AI & Privacy Governance
- **Data Minimization:** Only the sanitized task title string is sent to the model. Passwords, JWT tokens, user emails, and internal database IDs are strictly excluded from AI prompts.
- **Human-in-the-Loop:** AI output is treated strictly as an *editable draft/suggestion*, never as final truth. The user reviews and edits the suggestion before committing it to MongoDB.
- **Transparency:** The UI explicitly displays an AI disclaimer badge, notifying users that the text was generated by a machine learning model.

## 3. Architecture & Data Flow

```
React Frontend (localhost:5173)
       │
       ├─► User inputs Task Title: "Optimize MongoDB indexing"
       ├─► Clicks "✨ Auto-Describe"
       │
       ▼ (HTTP POST /api/ai/generate-description)
Express Backend Gateway (localhost:5000)
       │
       ├─► 1. Rate Limiter Middleware (Max 5 requests/min per IP)
       ├─► 2. Input Length Validation (3 - 150 chars)
       │
       ▼
 [AI Service Layer (aiService.js)]
       │
       ├──► Loads GEMINI_API_KEY securely from backend .env
       │
       ├──► (A) If Key Missing / Offline / Error:
       │         └── Catch error ──► Return { fallback: true, description: "" }
       │                             (App remains fully functional)
       │
       └──► (B) If Key Present & Online:
                 └── Request to Google Gemini 1.5 Flash (with 8s AbortController timeout)
                 └── Parse generated candidate text
                 └── Return { fallback: false, description: "...", disclaimer: "..." }
       │
       ▼
React Form
 └── Displays editable text in textarea + AI disclaimer badge
 └── Student reviews/edits description
 └── Clicks "Save Task to Database" ──► Persisted in MongoDB with isAiGenerated: true
```

## 4. Implementation Steps

1. **AI Service Module (`backend/src/services/aiService.js`):**
   - Implements native fetch calling Google Gemini 1.5 Flash (`generativelanguage.googleapis.com`) or OpenAI (`api.openai.com/v1/chat/completions`).
   - Uses `AbortController` with an 8-second timeout to prevent hung HTTP connections.
   - Detects unconfigured or placeholder keys and triggers graceful fallback mode.
2. **Rate Limiting (`backend/src/middleware/rateLimiter.js`):**
   - Sliding window limiter capping requests to `AI_RATE_LIMIT_PER_MINUTE` (default: 5) per client IP.
3. **Task API (`backend/src/routes/taskRoutes.js`):**
   - MongoDB schema includes `isAiGenerated: Boolean` to trace machine-assisted entries.
4. **React UI (`frontend/src/components/TaskForm.jsx`):**
   - Interactive "Auto-Describe" button with spinner.
   - Populates editable textarea.
   - Clearly flags machine-generated suggestions with accessible status alerts.

## 7. Viva Questions & In-Depth Answers

### Q1: Why must the AI API key be stored and invoked only from the backend rather than the React frontend?
**Answer:** The React frontend runs entirely in the user's browser client. Any environment variable or constant embedded into the client bundle (e.g. `VITE_API_KEY`) is directly visible in browser developer tools and network logs. Malicious users can extract the key, bypass all rate limits, and consume the account's quota or credit. Storing the key in the server's `.env` ensures it never leaves the trusted backend environment.

### Q2: What does "graceful degradation" mean in this practical, and why is it critical for third-party AI integrations?
**Answer:** Graceful degradation is the architectural principle that when a non-essential or third-party service fails, the overall system continues to function with reduced capability rather than experiencing a catastrophic crash. In this application, Generative AI is an assistive enhancement; if the AI API times out, runs out of quota, or fails authentication, the server returns a structured fallback notification, and the user can still create, edit, and manage their tasks manually without disruption.

### Q3: What are the privacy, data governance, and compliance implications of integrating external LLM APIs?
**Answer:** When sending data to external public AI providers, the prompt data may be processed on remote servers and potentially logged. Under regulations like GDPR or enterprise data policies, sending Personally Identifiable Information (PII), proprietary algorithms, passwords, or customer records to an external model without authorization is a critical compliance violation. Our implementation adheres to data minimization: only the short task title is transmitted, while sensitive user metadata remains strictly localized.

### Q4: Why is it important that AI-generated descriptions are rendered as editable fields rather than read-only?
**Answer:** Large Language Models frequently produce hallucinations—factually inaccurate, irrelevant, or overly verbose text. Maintaining a "human-in-the-loop" paradigm ensures that the human user retains agency and accountability. By rendering the description in a standard editable `<textarea>`, the student can correct false assumptions, adjust priority, or append domain-specific details before persisting the record into the database.

### Q5: How does the sliding window rate limiter prevent API abuse?
**Answer:** An in-memory sliding window rate limiter tracks client IP addresses and records the timestamp of each incoming request within a 60-second window. When a new request arrives, timestamps older than 60 seconds are purged. If the count of recent timestamps equals or exceeds the defined limit (e.g. 5 requests), subsequent calls are rejected with HTTP 429 Too Many Requests, preventing automated scripts from exhausting third-party API quotas.
